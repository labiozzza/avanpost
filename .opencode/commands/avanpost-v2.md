Ты — ведущий исполняющий разработчик проекта Avanpost. Находясь в Git-корне проекта, открой и прочитай файл `AVANPOST_V2_MASTER_SPEC.md` полностью, не пропуская разделы. При наличии прочитай `Avanpost_GDD_v0.9.md` или `docs/reference/Avanpost_GDD_v0.9.md`, а также `docs/plans/peace-sideview-migration.md` или `docs/reference/peace-sideview-migration_ARCHIVE.md`. Более позднее прямое решение пользователя — строить новый мирный spatial core V2, не мигрируя старую геометрию как обязательную часть — приоритетно в соответствующих границах GDD.

Этот slash-command — **не просьба только составить план**. Реализуй проект самостоятельно в Build-режиме, по всем доступным воротам G0–G11 из мастер-ТЗ, от аудита до проверенного играбельного мирного Stage I. Выполняй команды, создавай/редактируй файлы, проверяй, запускай сервер и браузер, исправляй регрессии, создавай отдельные безопасные коммиты. Нельзя остановиться после отчёта или плана. Пользователь не пишет код и не вводит команд в терминале.

Применяй доступные gstack skills из OpenCode: `gstack-autoplan` для reviewed plan на старте (при отсутствии — последовательно `gstack-plan-ceo-review`, `gstack-plan-design-review`, `gstack-plan-eng-review`), затем `gstack-review` на каждом пакете и `gstack-qa`/`gstack-design-review` по запущенному браузерному клиенту; `gstack-ship` только в финале для **безопасной feature-ветки/PR**, без merge/deploy. Загрузи skill инструментом OpenCode при наличии. Если gstack установлен не для OpenCode — безопасно настрой `./setup --host opencode` по официальному README. Не симулируй skills, которые не запускались. Защитные ограничения ТЗ обязательны даже при недоступных hooks.

В начале прочитай `docs/v2/STATUS.md` и `docs/v2/NEXT_ACTION.md`. Если это повторный запуск команды, продолжи с первой незавершённой задачи. При каждом gate фиксируй реальные проверки, commit SHA и следующий шаг, чтобы сессия могла быть возобновлена. Без напоминаний переходи к следующему безопасному gate; при непоправимом внешнем блокере продолжай независимые задачи и выдавай только точный запрашиваемый доступ.

Приоритет вначале — **ранний интерактивный G2**, который пользователь реально открывает в браузере и на телефоне. Не видео. Никакой top-down перспективы. Дальше — настоящая серверная side-view экономика и весь мирный этап I GDD. Старая БД и сохранения неприкосновенны, новые данные в отдельном V2 dev/test DB. Не делать reset/force push/merge/deploy в production, не реализовывать PvP до отдельной ручной приёмки мирного этапа.

Промежуточные сообщения коротко: gate, реальный runnable URL при наличии, что уже работает, какой тест прошёл. В финале дать status по форме §16 мастер-ТЗ. Работай, а не возвращай задание обратно владельцу.
