# Изолированные тестовые миры Peace V2

## Быстрая ручная проверка

В отдельном терминале выберите сценарий. Команда идемпотентно создаёт базу `avanpost_v2_manual`, применяет актуальные миграции, записывает новый `peace-home` и запускает только ручной API/client:

```sh
npm run prepare:peace:v2:manual -- --list
npm run prepare:peace:v2:manual -- construction-role-transition
```

Команда выводит БД, окружение, world ID, schema version, ресурсы, количество жителей/построек и длительность; после готовности печатает URL. Ручная игра: <http://localhost:15174/>. Подключите браузер обычным одноразовым кодом локального запуска.

Повторный запуск команды останавливает только PID `.gstack/run/peace-v2-api-manual.pid`, заново применяет схему/сценарий, очищает command/session записи manual-БД и снова запускает ручную игру. `avanpost_v2_dev`, `avanpost_v2_test`, их PID и порты не меняются. Для отдельной остановки: `npm run dev:peace:v2:manual:stop`.

## Каталог сценариев

| Сценарий | Проверяемое исходное состояние |
|---|---|
| `empty` | Два свободных жителя, пустые запасы, источники истощены, заказов и строений нет |
| `basic` | Два жителя, доступные деревья и камень, пустой склад |

| `construction` | Житель с ролью `builder`, ресурсы и два ожидающих домика |
| `construction-role-transition` | Два ожидающих заказа и житель без роли; назначьте Илье «Строитель» и наблюдайте очередь |
| `construction-blocked` | Строитель и заказ домика, которому не хватает древесины |

| `multi-worker` | Четыре жителя, два строителя и два заказа для проверки уникального распределения |

| `g5-construction-layout` | Готовые дом/мастерская, два склада, метка неустойчивого грунта `x=0`, узкий проход `x=12..20`, носильщик с грузом и допустимое место для дома |

Встроенный Playwright smoke загружает каждый сценарий в Phaser-клиент, сверяет world preview, версии, жителей, ресурсы и строения. Фабрики сценариев лежат в `apps/server-v2/src/testing/world-scenarios.ts`; итоговый снимок валидируется `PeaceWorldSnapshotSchema` перед транзакционным сбросом. Повторный сброс одного сценария воспроизводим.


G5.1 хранит `visualFeature` поверхности только для отображения: `unstable-ground` помечает слабый участок, `narrow-passage` — ограниченный проход. Метки не участвуют в разрешении строительства: опору и блокировку маршрута сервер вычисляет по `supportsBuilding`, `walkable`, footprint и графу проходимости.

### G4.1 — два склада и физическая доставка

1. Откройте `g4-multi-storage` и подключите только этот браузер обычным local pairing flow. Не пересылайте одноразовый код.
2. Выберите каждый склад в Phaser-сцене: в контекстном меню видны отдельные запасы и вместимость. Главный склад стартует полным; второй расположен у рощи и принимает груз.
3. Наблюдайте worker «Носильщик»: пока свободен, он сам берёт древесину/камень из источниковых буферов и идёт к доступному складу. Буферные счётчики и складские запасы меняются только при серверных load/unload фазах.
4. Выберите носильщика, затем свободный склад и назначьте его целью. Если у него уже есть груз/задача, дождитесь безопасного завершения текущего маршрута и повторите назначение.
5. Посмотрите на `Мастерскую`: она начинает ждать/получать древесину и камень через hauling reservations. Строитель берёт материалы только после фактической доставки и завершает заказ. После завершения носильщик снова обслуживает буферы.
6. Перезагрузите страницу. Логика продолжает жить на сервере; маршрут, cargo, buffers, warehouse stock и worksite transit reservations сохраняются также через API restart (автоматически покрыто изолированным API regression test).

Если второй склад заполнится, носильщик ждёт настоящего освобождения места; ресурсы не переносятся мгновенно. Баланс fixture (вместимость 16, стартовый груз и workshop recipe) временный и только для плейтеста.

## Изоляция

- Обычная игра и сохранение владельца: `avanpost_v2_dev`, `http://localhost:4175/`.
- Автоматические тесты: `avanpost_v2_test`, только Playwright; стандартные порты API/client `18888/14174/14175`, PID с суффиксом `-test`, один worker.
- Ручные проверки: `avanpost_v2_manual`, `http://localhost:15174/`, API `19888`, отдельный handoff/client и PID с суффиксом `-manual`.
- CLI сброса разрешает только operation `test` или `manual`, проверяет реальную БД/peer после подключения и блокируется в `NODE_ENV=production`. Неправильно указанная `avanpost_v2_dev` отвергается по фактическому имени БД.
- Сброс ручной БД не выполняет резервное копирование: в ней нет владельческого прогресса. Административная операция над `avanpost_v2_dev` остаётся отдельной, не входит в `prepare:peace:v2:manual` и никогда не вызывается из E2E.
