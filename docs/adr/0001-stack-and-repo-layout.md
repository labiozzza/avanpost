# ADR 0001 — Стек и структура репозитория

Статус: принято 2026-10-20. Основание: GDD v0.9, разделы 20 и 24.2 (P1 — стек не был утверждён).

## Решение

- Клиент: Phaser 3 (3.90), TypeScript, Vite, PWA через `vite-plugin-pwa`.
- Сервер: Node.js, Fastify 5, PostgreSQL, Kysely + SQL-миграции.
- Симуляция: отдельный пакет на чистом TypeScript с детерминированным seed-RNG.
- Репозиторий: npm workspaces, `apps/client`, `apps/server`, `packages/shared`, `packages/sim`.
- UI: DOM overlay на чистом TypeScript поверх Phaser.
- Идентичность I.0: анонимная серверная device-сессия через HttpOnly cookie.

## Почему

GDD требует server-authoritative состояние, физическую логистику, транзакционные леджеры и детерминированный повтор PvP. Пакет `sim` без DOM и БД позволяет тестировать детерминизм отдельно от сервера и клиента. Kysely оставляет SQL и транзакции явными, что важно для `entity_version`, резервов и outbox. Phaser 3 выбран как проверенная версия; Phaser 4 требует отдельного spike по камерам и replay (GDD 20.1).

## Последствия

- `npm install` обязателен в корне; пакеты связаны workspaces.
- Клиент и сервер общаются только через `/api`; в dev/preview работает Vite-прокси.
- Все количества и версии состояния — целые; время — серверное.
- Локальный кеш клиента не создаёт авторитетных ресурсов.

## Отклонённые варианты

- Один пакет: дешевле на старте, но размывает границы доменных модулей этапа I.
- Prisma: скрывает конкурентные SQL-апдейты, нужные для оптимистичной версионности.
- React: лишний слой для I.0; допускается позже для сложных панелей.
- Email/пароль в I.0: задерживает каркас; привязка аккаунтов остаётся расширением `identity`.
