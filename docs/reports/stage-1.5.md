# Отчёт по стабилизации этапа I.5 и миграции на Phaser

Дата: 2026-10-23. Ветка: `stabilize/stage-1.5`.
Коммиты: `938df8e` (пакет A), `f3c67fd` (Phaser-клиент, размещение, занятость жителей).
Версия сборки: `0.4.0`. Версия баланса: `1` (`proposed`).

## Итог

Этап I.5 стабилизирован: клиент больше не ведёт собственную экономику и не задаёт
тики, сервер остаётся единственным источником времени и состояния. Активный клиент
переведён на Phaser, старая Canvas-реализация удалена. Размещение зданий работает
призраком по сетке мышью и тачем. Занятость жителей учитывает обучение в школах.

## Что сделано

### Время и офлайн-прогресс (пакет A)
- Серверное ленивое догоняющее время (`last_simulated_at`, ADR-0005): любой запрос
  сначала доводит мир до `now`; тик обрабатывается по одному.
- Клиентские `ticks` удалены; `/api/commands/advance` только синхронизирует снимок.
- Догоняющий цикл клиента с `catchingUp` и бюджетом `maxCatchupTicks = 5000`.
- Детерминизм: одинаковые 100 тиков одним блоком и десятью блоками дают идентичное
  каноническое состояние.

### Единый Phaser-клиент (пакет F7)
- Активный клиент: `apps/client/src/phaser/main.ts` + `apps/client/src/game/scene.ts`.
- Удалены legacy-слои: `src/simple/main.ts` (2551 строка), `src/main.ts`,
  `ui/overlay.ts`, `net/api.ts`, `state/cache.ts`, старые стили.
- HUD, жители, школы, ремесло и исследования читают `WorldSnapshot`; локального
  `wood` и клиентских таймеров нет.
- Исправлена проекция камеры: `screenPointFor()` считает через `camera.worldView`.
  До исправления клики и хотспот дерева смещались относительно клеток.

### Размещение зданий по сетке
- Вместо координатного меню `placement-picker` — режим призрака: сетка, зелёная
  клетка (можно), жёлтая (ждут материалы), красная (нельзя).
- Мышь подтверждает сразу; на тач-устройстве первый тап выбирает клетку, второй
  подтверждает. Escape, правый клик и «Отмена» выходят из режима.
- `409` от сервера сохраняет режим, показывает причину и перечитывает мир; материалы
  на клиенте не списываются. Итоговое решение всегда за сервером.

### Жители и школы
- `WorldRun.availableLaborers()` исключает учащихся из назначений carrier/builder/gatherer.
- `send-school` отклоняет занятого жителя (`RESIDENT_BUSY`).
- Рубка принимает явный `resident_id`; проверяются владелец, статус и наличие idle-добытчика.
- На сцене школы и учащиеся видны по серверным `training.leftTicks/totalTicks`.

## Проверки

| Команда | Результат |
|---|---|
| `npm run typecheck` | без ошибок, все 4 workspace |
| `npm test` | 7 файлов, 88 тестов — зелёные (3 прогона подряд) |
| `npm run build` | сервер + клиент + PWA, без ошибок |
| `npm run e2e` | 18 passed: 9 desktop + 9 mobile |
| `/api/health` | `ok`, `buildVersion 0.4.0`, `balanceVersion 1` |

E2E покрывают: стартовые ресурсы (45 брёвен, 35 камня), рубку и рост запаса,
сохранение активной рубки после reload, постройку дома призраком, отмену размещения,
обучение в школе с сохранением после reload и опытом, постройку мастерской/академии,
исследование без учёного, полный цикл «плотницкое дело → доска», PWA-манифест.

## Отклонения и долги

- Мир и здания по-прежнему рисуются процедурно через `Graphics`; PNG-ассеты
  используются только в CSS/HUD. Подключение спрайтов — отдельная задача.
- Footprint зданий ограничен 1×1; поле `footprint` в протоколе уже есть.
- Школы — визуальные клетки клиента, без отдельного серверного здания.
- CI-workflow не запушен: у текущего PAT нет scope `workflow`.
- Исторические планы I.1–I.5 оставлены как есть; актуальное состояние — этот отчёт
  и `docs/plans/stage-1.5-stabilization.md`.

## Вывод

Критерии стабилизации I.5 выполнены: сервер авторитетен по времени, экономике и
занятости; клиент — единая Phaser-реализация с сеточным размещением и серверными
состояниями; тесты и сборка зелёные. Следующий визуальный шаг — подключение
существующих PNG-спрайтов вместо процедурной отрисовки.
