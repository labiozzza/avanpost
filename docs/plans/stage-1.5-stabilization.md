## Архитектура (после stabilizации)

### Время (пакет A)
- **Решение (ADR-0005):** серверное ленивое догоняющее время. `world_state.last_simulated_at` — отметка последнего рассчитанного тика. Любой аутентифицированный вызов (`/api/state`, `/api/session`, любая команда) сначала догоняет мир до `now`.
- Тик всегда обрабатывается **по одному** (`loop processedTicks × advanceStep(1)`): свойство разбиения A3 выполняется конструктивно (D07).
- Бюджет: `max_catchup_ticks` за один запрос (конфиг); остаток сохраняется в `last_simulated_at` — тихой потери нет.
- Клиентские `ticks` из `AdvanceCommandSchema` удалены; endpoint `/api/commands/advance` синхронизирует и возвращает снимок, сервер сам считает прошедшее время по `TICK_MS`.
- Тест-контроль времени только при `AVANPOST_TEST_TIME_CONTROL=1` (dev/test сервер): маршрут `/api/test/set-clock`; production не устанавливает флаг.

### Экономика (пакет B)
- Клиентская рубка (выбор дерева → `gather` → анимация из снимка → `haul` → склад) полностью из серверных данных; локальный `wood` удалён. HUD читает `storages[].contents` + `in transit` (transfer/haul tasks) + `reserved`.

### Жители (пакет C)
- Единый `residentOccupied(residentId)` узел: laborer-привязка (gatherer/builder/перeвозчик), активный craft_order, research_project. Используется в `startCraft`, `startResearch`, `sendSchool`, `gather`.
- Опыт за фактически завершённые задачи (gather-завершение партии, завершение крафта, доставка).
- Снос станции: активный заказ отменяется, буфер вывозится; житель освобожден.

### Исследования (пакет D)
- Профессия «Учёный» через новую гражданскую школу `science` (расширение SIM-механики школ, [П] из GDD §4.3 по минимуму).
- Жизненный цикл: start/assign/смена/пауза/резюме/отмена/закрытие; `research-replace-scholar` не теряет прогресс.
- RP: прогресс проекта = научная работа (units); `research_points` игрока — накопленная работа (статистика/денность для будущего), расход не введён. UI подписан честно.
- masonry реальный эффект: рецепт `bricks` (каменотёс, stone 2 → brick 1, станция workshop).

### Логистика (пакет E)
- Один расчёт доступности: `available = физический объём − все активные резервы (haul+transfer) − буферы`, учёт `item.volume` по вместимости буферов и складов (D11).
- Отмена крафта/снос — освобождение и вывоз материалов; инварианты тестами (неотрицательность, без двойных расходов, одна партия).

## Порядок работ
A (время) → B (единая экономика) → C (жители) → D (исследования) → E (логистика) → G (надёжность) → F (UI/визуал) → H (тесты/CI) → I (приёмка).
