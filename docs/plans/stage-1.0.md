# Этап I.0 — технологический каркас

Источник: `Avanpost_GDD_v0.9.md`, разделы 20, 21.1 (пакет I.0), 23.

## Цель пакета

Играбельный каркас: чистая установка, серверная сессия, авторитетный снимок мира, Phaser-сцена, PWA shell, сохранение и версия сборки. Никаких производственных цепочек и строительства — это I.1–I.3.

## Принятый объём

- npm workspaces и единая команда установки.
- Fastify API: health, session, state, heartbeat, advance.
- PostgreSQL-миграции и репозитории на Kysely.
- Один сектор 64×24, детерминированный рельеф из seed, посёлок-площадка.
- `world_state.version` + оптимистичная проверка `expected_version`.
- Идемпотентность команд по `request_id` и журнал `command_log`.
- Outbox-событие `WorldAdvanced` в той же транзакции.
- Клиент: Phaser-сцена, drag/zoom камеры, DOM-панели, кнопка «Прожить 1 тик».
- Локальный кеш последнего снимка и офлайн-сообщение.
- PWA manifest + service worker, версия сборки в UI.
- Тесты: unit симуляции, integration API на реальном Postgres, Playwright desktop+mobile.

## Вне объёма I.0

- Строительство, логистика, жители, школы, наука, королевские заказы (I.1–I.6).
- Финальный арт, атласы, анимации, звук (I.7).
- PvP, рынок, лиги (этап II).
- Email/пароль и восстановление аккаунта.
- Полные P0-реестры баланса (`items.yaml`, `buildings.yaml` и т.д.) — вводятся пакетами I.1–I.5.

## Инварианты приёмки

- Повтор команды с тем же `request_id` не увеличивает версию и тик.
- Устаревшая `expected_version` даёт `409 STALE_VERSION`.
- Клиент не может создать ресурсы без подтверждения сервера.
- Время и версия состояния — серверные.
- Симуляция детерминирована по seed.
- При закрытии и повторном открытии тик сохраняется.

## Риски и долги

- P0-баланс не закрыт: числа 64×24, 5 типов рельефа и стартовая площадка помечены как `proposed` до пакета I.1.
- Иконка PWA — SVG; PNG 192/512 добавить в I.7 вместе с арт-реестром.
- Device-сессия не восстанавливается между устройствами; привязка аккаунта — расширение `identity`.
- Офлайн-режим только читает кеш; авторитетных офлайн-действий нет (соответствует GDD 20.6).
- Полноценный replay и фиксированный шаг симуляции появятся вместе с боевым модулем этапа II.

## Доказательства

- `npm run typecheck` — типы всех пакетов.
- `npm test` — unit + integration на Postgres.
- `npm run e2e` — реальный клиент и сервер, desktop и mobile, скриншоты в `docs/evidence/`.
- `npm run build` — сборка клиента с PWA-манифестом и сервера.
